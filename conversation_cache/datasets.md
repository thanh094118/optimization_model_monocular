# Datasets

## Core Paths

- Camera videos:
  - `input/video_1.mp4`
  - `input/video_2.mp4`
- Camera calibration source:
  - `input/camera.calibration`
- Generated camera profiles:
  - `output/preprocess_results/data_cam1.json`
  - `output/preprocess_results/data_cam2.json`
- Ground truth for evaluation:
  - `input/gtruth_results/ground_truth_*.json`

## Camera Profile Fields (Current)

- `intrinsics_cam`: intrinsics from calibration file
- `intrinsics_estimation`: estimated intrinsics from video dimensions
- `extrinsic_cam`: 3x3 rotation
- `tvec`: translation vector (extrinsic 4th column)
- `offset_paper`, `offset_colab`
- `2D_camera_cam1` / `2D_camera_cam2`: WHAM `tracking_results_for_reproj` 2D keypoints mapped to project joint names as `[x, y, confidence]`, keyed by original WHAM `frame_id`
- `shape` / `init_betas`: WHAM `tracking_results_for_reproj.init_betas`, usually shape `(1, 10)`

## WHAM 2D Tracking Map

- Source PKLs:
  - `input/wham_opencap_1.pkl`
  - `input/wham_opencap_2.pkl`
- Loader:
  - use `joblib.load()`, not plain `pickle.load()`
- Source payload:
  - top-level `defaultdict` with person key `0`
  - `tracking_results_for_reproj.frame_id`, shape `(frames,)`
  - `tracking_results_for_reproj.keypoints`, shape `(frames, 133, 3)`
  - `tracking_results_for_reproj.init_betas`, shape `(1, 10)`
- Mapping from 133-keypoint source to project names:
  - `neck: 0`
  - `right_shoulder: 6`
  - `right_elbow: 8`
  - `right_hand: 10`
  - `left_shoulder: 5`
  - `left_elbow: 7`
  - `left_hand: 9`
  - `right_hip: 12`
  - `right_knee: 14`
  - `right_ankle: 16`
  - `left_hip: 11`
  - `left_knee: 13`
  - `left_ankle: 15`
  - `right_foot: 21`
  - `left_foot: 18`

## HBH Outputs

- Per-method 3D/key2D files:
  - `output/hbh_results/method_<method>/hbh_data_<frame>.json`
- Per-method PA-MPJPE CSVs:
  - `output/hbh_results/pa_mpjpe_hbh_<method>.csv`
- Combined projection visualization:
  - `output/hbh_results/hbh_project_5col.mp4`

## Runtime Requirements

- HBH requires:
  - Ultralytics-compatible model file configured in `hbh.model`
  - OpenCV-readable videos
  - camera profiles generated by preprocess stage

## Learnable Assets And Inputs

- Learnable stage consumes:
  - `output/fused_results/keypoints3d/fused_data_*.json`
  - `input/wham_opencap_1.pkl`, `input/wham_opencap_2.pkl`
- Learnable stage runtime assets expected by NetBody25:
  - `models/smpl/J_regressor_body25.npy`
  - `models/smpl/SMPL_NEUTRAL.pkl`
  - `models/smpl/SMPL_MALE.pkl`
  - `models/smpl/SMPL_FEMALE.pkl`
- Project config sources commonly used to populate those assets:
  - `paths.j_regressor_body25` (default: `models/J_regressor_body25.npy`)
  - `paths.smpl_model` (default: `models/SMPL_NEUTRAL.pkl`)

## Standalone Optimization Inputs And Outputs

- Shared config file:
  - `optimization_pipeline/configs.yml`
- Default standalone phase input area:
  - `optimization_pipeline/data/`
- Default standalone phase output area:
  - `optimization_pipeline/output/`
- Default chained intermediates:
  - `optimization_pipeline/output/phase2_params.pkl`
  - `optimization_pipeline/output/phase3_params.pkl`
  - `optimization_pipeline/output/phase4_params.pkl`
  - `optimization_pipeline/output/phase5_params.pkl`
  - `optimization_pipeline/output/phase6_params.pkl`
- Optional optimization summaries:
  - `optimization_pipeline/output/phase5_summary.json`
  - `optimization_pipeline/output/phase6_summary.json`

## Standalone Optimization Payload Expectations

- `params` payload should contain SMPL arrays keyed by:
  - `Rh`
  - `Th`
  - `poses`
  - `shapes`
- `keypoints` payload is expected as 2D keypoints with shape `[frames, joints, 3+]` where the first three values are `x, y, confidence`.
- `cameras` payload is expected to contain:
  - `K`
  - optional `R`
  - optional `T`
- Phase 2, 5, and 6 use these model assets from config by default:
  - `models/SMPL_NEUTRAL.pkl`
  - `models/J_regressor_body25.npy`
